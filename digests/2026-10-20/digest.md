## Vector-Quantized World Model: Latent Feedback Motion Planning for Robot Manipulation
- **arXiv:** 2610.25600 · https://arxiv.org/abs/2610.25600
- **Submitted:** 2026-10-19
- **Authors:** Xuezhou Xu, Chung-Pang Wang, Zhenzhen Li, Benjamin Riviere
- **Qualifying affiliation(s):** NVIDIA — affiliation block lists "New York University" and "NVIDIA" without an explicit per-author mapping in the fetched HTML
- **Categories:** cs.RO
- **Open release:** none found
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** The paper proposes VQ-WM, a latent feedback motion planner that searches over vector-quantized latent states (using a learned world model) for short paths to a goal, while a separate continuous visual-feedback controller tracks each planned state and corrects drift. Quantization uses a first-passage-time (FPT) quasi-metric, estimated via closed-loop rollouts, instead of Euclidean distance, so codes reflect what the controller can actually reach.

**Purpose (≤3 sentences):** The authors target long-horizon robot manipulation and locomotion planning, where visual world models typically fail because autoregressive prediction errors compound and long action sequences are hard to optimize directly.

**Breakthrough (≤3 sentences):** On a physical four-disk Tower of Hanoi task (WidowX arm), the authors report 100% success on the full 15-move solution using only short "play" demonstrations, versus baselines Cosmos Policy (5%), π0.5 (3%), and V-JEPA 2-AC* with manual subgoals (27%) on non-expert data. On simulated long-horizon manipulation benchmarks (Stable-WorldModel), they report VQ-WM beating the strongest prior world model (H-JEPA) by 8.0–28.0 percentage points, and on DeepMind Control Walker locomotion with images only, 22.0% vs 12.7% for DINO-WM (97.3% vs 12.0% with proprioception added).

**Tools & method (≤3 sentences):** The pipeline uses a frozen V-JEPA 2 encoder, a goal-conditioned controller, a continuous latent predictor, and a discrete latent predictor/codebook built via a greedy set-cover over FPT-estimated regions of attraction. At inference, breadth-first search over the discrete latent graph plans the path, and the authors report a ~5-minute robot execution plan computes in under one second on an NVIDIA RTX 5080 GPU.

**Limitation (≤3 sentences):** The authors note experiments use only a single plan per episode, so the benefits of replanning are unexplored, and the method relies on a learned latent world model for its FPT reachability estimates (with a rejection class excluding unseen transitions from graph search). They flag an inconsistency between the abstract's reported gain range (13.3–85.3 points) and the introduction's narrower comparison (13.3–34.6 points vs H-JEPA specifically).

## State World Models: Execute the Rules, Generate the Pixels
- **arXiv:** 2610.26811 · https://arxiv.org/abs/2610.26811
- **Submitted:** 2026-10-19
- **Authors:** Chan Yan Ki, Yanran Zhang, Wenzhao Zheng, Xiaofeng Wang, Zheng Zhu, Lei Chen, Jie Zhou, Jiwen Lu
- **Qualifying affiliation(s):** GigaAI (co-affiliation alongside Dept. of Automation, Tsinghua University); FLAG: borderline
- **Categories:** cs.CV
- **Open release:** none
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** The paper introduces a "Stateful Harness" that separates world-state evolution from video rendering so that identical visible actions produce outcomes consistent with hidden state and explicit rules, plus WorldState-Bench, a set of 50 counterfactual pairs sharing a first frame and action but differing in hidden state (49 hidden variables, 21 themes). On WorldState-Bench, the best unwrapped video backend reaches 32% PairFollow under rule-only prompting, while the same frozen video weights (MiniMax-H3) reach 92% inside the full harness.
**Purpose (≤3 sentences):** To test and support "state world models," where the same visible action should yield different outcomes depending on hidden state, evaluated against rules specified up front rather than left to the video model to infer.
**Breakthrough (≤3 sentences):** The authors report that wrapping a frozen, unmodified video model in their rule-resolution runtime raises PairFollow from 32% to 92%, i.e. no engine integration or model fine-tuning is required to make video generation obey hidden-state rules. They also report human blind-preference tests and an external comparison against "WBench" supporting the harness's gains.
**Tools & method (≤3 sentences):** The runtime resolves each user action against a semantic ledger and an editable 3D scene using fixed rules, compiles the resolved event into a text instruction plus a 3D-scene preview clip for spatial guidance, and has a frozen video model render it while a VLM (Qwen3.8-27B-VL) updates state for the next turn. First frames were generated with FLUX.2; eleven existing video backends were evaluated; generation/judging ran on eight A800 80GB GPUs.
**Limitation (≤3 sentences):** The authors state that rendering remains stochastic and zone-triggered state cases are the most demanding for the harness. Judging relies on a VLM judge, validated only against a human-audited subset, and unclear clips receive no credit.

## Simulation Priors for Rapid Adaptation in Model-Based RL for Autonomous Racing
- **arXiv:** 2610.26757 · https://arxiv.org/abs/2610.26757
- **Submitted:** 2026-10-19
- **Authors:** Adrian Remonda, Jiajun Xi, Nicklas Hansen, Marcus Greiff, Thomas Lew, John Talbot, John Subosits, Xiaolong Wang
- **Qualifying affiliation(s):** Toyota Research Institute (Los Altos, CA); FLAG: borderline
- **Categories:** cs.LG, cs.RO, eess.SY
- **Open release:** none (authors state they release code and datasets, but no link was located)
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** The paper proposes Prior-Informed Adaptation (PIA), an offline-to-online model-based RL framework for autonomous racing that pretrains a world model on low- and high-fidelity simulated trajectories, then adapts it online with limited real interaction. It is evaluated in high-fidelity simulation and on a full-size autonomous race car.
**Purpose (≤3 sentences):** To address the high cost and risk of RL data collection in settings like racing, enabling quick adaptation to new tracks/surfaces without requiring an exact simulator.
**Breakthrough (≤3 sentences):** The authors report that treating simulated trajectories as biased priors — rather than as an environment for direct policy transfer — combined with a mixed sim/target replay buffer and uncertainty-regularized latent planning (Q-ensemble disagreement) enables adaptation validated on a real full-size race car (the F317).
**Tools & method (≤3 sentences):** Assetto Corsa Gym (ACGym), a high-fidelity racing simulator, plus a lightweight low-fidelity ODE vehicle model sharing ACGym's interface; the authors report a released dataset covering 15 tracks and more than 740 hours of Assetto Corsa driving data, with simulation experiments on 9 tracks.
**Limitation (≤3 sentences):** The authors state PIA requires a model/simulator sharing the target's observation-action interface, making image- or LiDAR-heavy inputs harder to use, and that experiments focus on dynamics mismatch rather than strong exogenous randomness (e.g. opponent vehicles). The real-car study covers only one track/surface, and early deployments can fail when the real-data anchor is too small.

## PrismWAM: Decoupling State Representations in World Action Models
- **arXiv:** 2610.26564 · https://arxiv.org/abs/2610.26564
- **Submitted:** 2026-10-19
- **Authors:** Tianyu Xin, Wanqi Zhong, Bowen Hu, Zhangchi Guo, Lijie Wang, Yiming Wang, Haoran Liao, Heyang Yu, Xiaoyu Tian, Zhiding Yu, Yiming Li
- **Qualifying affiliation(s):** NVIDIA (co-affiliation alongside Tsinghua University)
- **Categories:** cs.CV
- **Open release:** demo — project page https://prism-wam.github.io/
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** PrismWAM argues that the video latents used by World Action Models (WAMs) conflate appearance (texture, color) with physical configuration (occupancy, pose), which is a poor state representation for action. It splits the task into semantic planning, physical rollout in depth space, and action generation, built on a pretrained video backbone (Wan).
**Purpose (≤3 sentences):** To determine what the internal "state" of a world-action model should be, and to argue it should separate how the world looks from how it physically changes under action.
**Breakthrough (≤3 sentences):** The authors report strong performance in both simulation and the real world without any embodied action pretraining, using sparse RGB goal supervision combined with dense depth supervision and a "chain attention" mask controlling information flow between an RGB planning stream and a depth rollout stream.
**Tools & method (≤3 sentences):** A Mixture-of-Transformers architecture (main model ~6B parameters, PrismWAM* variant 15B) with depth-VAE pretraining on ~2,300 hours of depth data from AgiBotWorld-Beta plus simulated RoboTwin depth; evaluated on RoboTwin 2.0, LIBERO/LIBERO-Plus/LIBERO-Pro, and RoboDojo, and on real single/dual-arm Piper-X robots with Orbbec Gemini 335 RGB-D cameras.
**Limitation (≤3 sentences):** The authors state that large-scale real-world manipulation data with synchronized depth remains limited, constraining how much depth pretraining is currently possible, though they expect this to improve as depth sensing becomes more accessible.

## PhysSkin++: Real-Time and Generalizable Physics-Based Animation via Self-Supervised Neural Skinning
- **arXiv:** 2610.26067 · https://arxiv.org/abs/2610.26067
- **Submitted:** 2026-10-19
- **Authors:** Yuanhang Lei, Baofei Liu, Xingxuan Li, Tao Cheng, Zixuan Wang, Boming Zhao, Yujun Shen, Siyuan Huang, Ruizhen Hu, Peter Yichen Chen, Hujun Bao, Zhaopeng Cui
- **Qualifying affiliation(s):** Ant Group — Yujun Shen; FLAG: borderline
- **Categories:** cs.CV (cross-listed cs.GR)
- **Open release:** demo — project page https://zju3dv.github.io/PhysSkin_plus/
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** PhysSkin++ is a physics-informed framework that learns continuous neural skinning fields from static 3D geometry to build compact deformation subspaces for real-time, generalizable physics-based animation, supporting meshes, point clouds, and 3D Gaussians as well as rig-complementary animation. It extends the authors' earlier conference paper, PhysSkin.
**Purpose (≤3 sentences):** To generalize real-time physics-based animation across different 3D shapes and spatial discretizations without relying on simulation trajectories or annotated skinning data.
**Breakthrough (≤3 sentences):** The authors introduce a rig-complementarity loss that lets the model learn physically-grounded elastic responses on top of artist-authored rig animation, and report supporting controllable, collision-aware animation with Dirichlet boundary conditions, user dragging, gravity, floor contact, and rigid/deformable multi-object contact.
**Tools & method (≤3 sentences):** A Neural Skinning Fields Autoencoder (transformer shape encoder + cross-attention decoder) is trained with a self-supervised strategy (PISSL) combining potential-energy, smoothness, and orthogonality losses with conflict-aware gradient correction (ConFIG). Evaluation uses ShapeNet, RigNet, a deformable Lego family from Mani-GS, ShapeSplat (3D Gaussians), and Mixamo sequences retargeted with Auto-Rig Pro, trained on 4 NVIDIA RTX 4090 GPUs.
**Limitation (≤3 sentences):** The authors state the current formulation "does not incorporate semantic priors for modeling complex geometries" and plan to explore such priors in future work.

## PVBench: Quantifying Physical Plausibility in Video Generation with Object-Level Physical Measurements
- **arXiv:** 2610.26711 · https://arxiv.org/abs/2610.26711
- **Submitted:** 2026-10-19
- **Authors:** Kaiwei Chen, Moran Li, Zhenye Gan, Yabiao Wang, Chengjie Wang, Kexin Zhang, Yong Liu, Jiangning Zhang
- **Qualifying affiliation(s):** Tencent — Tencent Youtu Lab
- **Categories:** cs.CV
- **Open release:** none (authors state intent to release the benchmark, prompts, and calibration protocol, but no link was found)
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** PVBench scores the physical plausibility of generated videos across 46 dimensions spanning seven domains, using 600 paired text-to-video/image-to-video prompt groups (30% involving embodied agents such as robot arms and humanoids). Specialized vision models produce measurements such as 6D pose, metric scale, surface normals, kinematics, and conservation-law residuals, mapped to 1–5 scores and validated against human judgments.
**Purpose (≤3 sentences):** To move evaluation of video generation from semantic impressions toward computable physical quantities checked against physical laws, moving video generation from "looking good" to "physically usable" as the authors put it.
**Breakthrough (≤3 sentences):** The authors evaluate six T2V/I2V model configurations (~7,200 videos total), including MiniMax H3, SANA-Video 2.0, Wan2.1, Wan2.2, Seedance 2.5, and LingBot-Video, reporting the protocol's physical scores track human judgment while most benchmark dimensions remain unresolved by current generators.
**Tools & method (≤3 sentences):** Paired T2V/I2V prompt groups were drafted with GPT-5.6 and screened by humans; reference images were made with GPT-image-2; a multimodal LLM scores only dimensions that are hard to quantify numerically (materials, phase change). Evaluation ran on a single H20 GPU with 10 annotators per human-validation sample.
**Limitation (≤3 sentences):** The authors note results depend on specialized vision models and that unobservable cases are skipped; material and phase-change dimensions still rely on MLLM scoring rather than measurement, and most dimensions lack ground-truth references.

## Mise-en-Video: Fine-Grained 3D Control for Multi-Shot Video Generation
- **arXiv:** 2610.26801 · https://arxiv.org/abs/2610.26801
- **Submitted:** 2026-10-19
- **Authors:** Yingshuang Zou, Xiaoyu Shi, Yawen Luo, Ziang Li, Qinghe Wang, Mengfei Li, Chengfeng Zhao, Xintao Wang, Pengfei Wan, Kun Gai, Yuan Liu
- **Qualifying affiliation(s):** Kuaishou — KlingAI Research (Xintao Wang, Pengfei Wan, Kun Gai)
- **Categories:** cs.CV, cs.AI
- **Open release:** none (a 160K-video dataset is described but no release link was found on the abstract page)
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** Mise-en-Video (MeV) is a framework for multi-shot video generation in which creators stage each shot in 3D before generation, combining hierarchical attention for cross-shot narrative consistency with 3D-aware layout guidance for per-shot spatial control. The authors also built a 160K-video dataset (2–6 shots, up to 250 frames each) with hierarchical captions and oriented 3D bounding boxes.
**Purpose (≤3 sentences):** To give creators fine-grained control over subject placement, orientation, and motion within and across shots of a multi-shot video while preserving consistency across shots.
**Breakthrough (≤3 sentences):** The authors report better video quality, inter-shot consistency, and subject-level control than baselines including MultiShotMaster and EchoShot, evaluated on 100 multi-shot prompts generated with Gemini 2.5.
**Tools & method (≤3 sentences):** Subject Layout Guidance encodes subjects as oriented 3D boxes with a NOCS-based color scheme, projects them into per-frame 2D layout maps, and injects them via a ControlNet-style branch; Hierarchical Context Attention splits text into global/shot/subject levels with masked attention. The data pipeline detects shots in web videos, tracks/reconstructs subjects in 3D, and captions with Gemini; training used a roughly 1B-parameter backbone on 32 GPUs.
**Limitation (≤3 sentences):** The authors state that overall generation quality is capped by the pretrained backbone's relatively small parameter count, limiting performance on high-quality dynamic videos, and they plan to use larger backbones and/or larger controllable modules.

## EmbodiedWorld-200K: Toward Embodied World Agents via Embodied-Planning Dataset and Interactive World Models
- **arXiv:** 2610.25959 · https://arxiv.org/abs/2610.25959
- **Submitted:** 2026-10-19
- **Authors:** Xiaokun Feng, Junshu Tang, Zeyi Lin, Ling-Hao Chen, Shuai Shao, Qinglin Lu, Kaiqi Huang
- **Qualifying affiliation(s):** Tencent Hunyuan — Xiaokun Feng, Junshu Tang, Zeyi Lin, Ling-Hao Chen, Shuai Shao, Qinglin Lu, Kaiqi Huang (paper states the work was done during an internship at Tencent Hunyuan)
- **Categories:** cs.AI
- **Open release:** code | checkpoints | dataset (paper states "dataset, checkpoints, and code are said to be publicly released"; no specific link found in fetched text)
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** The paper introduces "Embodied World Agents" (EWAs) and instantiates them as open-world embodied navigation planning. It releases EmbodiedWorld-200K, a 200K+ sample dataset built from about 260K gameplay trajectories (~708 hours) mined from OGameData (150+ 3D games), with multi-level annotations from camera motion to goal-navigation instructions. A two-stage recipe (offline SFT, then world-model RL) is proposed and evaluated.

**Purpose (≤3 sentences):** The authors argue existing embodied benchmarks are narrow (single scene, single robot, or single game) and that passive vision-language training lacks closed-loop perception-action ability. They build a large, multi-genre open-world planning dataset and a training recipe meant to generalize beyond the training distribution.

**Breakthrough (≤3 sentences):** The authors report that SFT on their dataset raises a Qwen3-VL-4B baseline from TM 54.9/DirAcc 70.1/nDTW 67.1/NE 51.7 to TM 62.0/DirAcc 72.0/nDTW 83.6/NE 35.6 on their own held-out split, roughly matching Gemini-3.5 on DirAcc (72.0 vs 72.4). On a GTA5 target-scene test, adding DPO trained inside the video world model LingBot-World-Fast raises TM from 65.4 to 75.0 and nDTW from 66.1 to 92.7, with NE falling from 48.9 to 13.4.

**Tools & method (≤3 sentences):** Camera poses are recovered with VIPE; clips are segmented into "navigation-coherent segments" with a shared W/A/S/D action vocabulary; Qwen3.5-27B generates instructions. Stage I is LoRA SFT (2 epochs) on Qwen3-VL-4B; Stage II runs the SFT model inside the video world model LingBot-World-Fast, using a VQA-based reward over rollouts to build DPO preference pairs.

**Limitation (≤3 sentences):** The fetched text's dedicated Limitations appendix was truncated, but visible section headers note "3D virtual games as proxies for the physical world" and "limited action granularity" as concerns. Stage II evaluation relies on a single target game (GTA5), and the underlying data is built entirely from virtual games rather than physical environments.

## Clean Forcing: Drift-Resistant Autoregressive Video Diffusion with a Frozen Base
- **arXiv:** 2610.25634 · https://arxiv.org/abs/2610.25634
- **Submitted:** 2026-10-19
- **Authors:** Wenqing Wang, Joonghyuk Shin, Jonathan Tremblay, Chan Hee Song, Yun Fu
- **Qualifying affiliation(s):** NVIDIA — Jonathan Tremblay, Chan Hee Song (affiliation block lists NVIDIA alongside Seoul National University and Northeastern University; footnote states one author's work was done during an NVIDIA internship and two authors are co-last authors)
- **Categories:** cs.CV, cs.LG
- **Open release:** demo (paper states "representative rollouts appear on the project page"; no link found in fetched text)
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** Autoregressive video diffusion models generate streaming video by conditioning each chunk on previously generated (imperfect) frames, which causes compounding "drift" that degrades quality within seconds. The authors show this drift is largely deterministic (~95% systematic across noise seeds) and train a small 5.9M-parameter LoRA corrector, "Clean Forcing," on a frozen base model to regress it, with a closed-loop DAgger-style training stage. The merged corrector needs no real video for training and adds no inference-time cost.

**Purpose (≤3 sentences):** The paper targets exposure bias in autoregressive video diffusion used for long, streaming video generation — including the kind of real-time generative world models used for driving and game simulation — where prior fixes required expensive full retraining or gave inconsistent training-free corrections.

**Breakthrough (≤3 sentences):** On 50-second text-to-video generation with Wan2.1-T2V-1.3B, the authors report Δ-drift falling from +11.3 (adapted base) to +1.65 using zero real videos, and to −0.16 using 40 real clips, which they say beats the best published result (+3.57) while using over 150× less data. Applying the same zero-real-video recipe to two other autoregressive world models, they report a 48% drift reduction on HY-WorldPlay and a 60% drift reduction on NVIDIA OmniDreams (a driving world model built on Cosmos-Predict2.5).

**Tools & method (≤3 sentences):** The corrector is a rank-16 LoRA (5.9M params, 0.4% of the base) on the q/k/v/o self-attention projections across all 30 DiT blocks, trained with AdamW; evaluation uses 128 held-out MovieGenVideoBench prompts and VBench + Δ-drift (MUSIQ-based) metrics. Training uses at most 340 clips (40 real + 300 synthetic) versus a cited baseline's 55K source/81K generated clips; the full pipeline runs in about one day on a single NVIDIA GB300 GPU (≥48 GB memory), with the 14B-model variant taking about three GPU-days.

**Limitation (≤3 sentences):** The authors state stronger drift reduction tends to coincide with less scene progression (corrected scenes stay close to their opening frames), and learned correctors transfer poorly to sibling checkpoints or a distilled four-step model (giving no benefit on Self-Forcing's distilled generator). They also report training instability at the 14B scale, making checkpoint selection important, and note the appendix's full Limitations section was truncated in the fetched text.

## ActionRoPE: action as coordinates for spatially consistent control in planar-camera game world models
- **arXiv:** 2610.25861 · https://arxiv.org/abs/2610.25861
- **Submitted:** 2026-10-19
- **Authors:** Zhiyang Deng, Yuzhe Wu, Zijun Lin, Yeying Jin
- **Qualifying affiliation(s):** Tencent — all four authors list Tencent as a primary affiliation, alongside National University of Singapore (Deng, Wu, Jin) and Nanyang Technological University (Lin)
- **Categories:** cs.CV
- **Open release:** none found
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** The paper targets action control in "planar-camera" game world models (top-down/isometric games), where existing feature-based action conditioning fits poorly because it gives the model no explicit world coordinate system. ActionRoPE converts action-driven camera displacement into world-coordinate rotary positions so the same world location keeps the same positional address over time, paired with Coordinate-Conditioned Noise Scheduling (CNS) that denoises already-seen regions earlier than newly revealed ones. Both additions are parameter-free or near-parameter-free (the knownness mask adds ~0.015M parameters).

**Purpose (≤3 sentences):** The authors want game world models that follow commanded motion faithfully and don't "drift" (regenerate a different scene) when a player returns to a previously visited location, a known failure of feature-conditioned action control.

**Breakthrough (≤3 sentences):** On their main Wan2.2-TI2V-5B backbone, the authors report the method improves PSNR from 21.11 dB (best baseline, AdaLN) to 23.94 dB and cuts drift from 22.6 px to 7.8 px — a reported 66% drift reduction over the strongest of four re-implemented baselines (Prompt, Linear, AdaLN, Cross-Attn). They report the method transfers across backbones from 1.3B to 33B parameters (SkyReels-V2-DF, LTX-2.5, MiniMax-H3) and to out-of-distribution scenes (drift 7.6 px vs 16.5 px for the best baseline).

**Tools & method (≤3 sentences):** Training data comes from the game *No Rest for the Wicked* (2.5D fixed top-down view): 50.9 hours, 22,782 clips at 81 frames/16 fps/832×480, with 18,528 training and 982 held-out evaluation clips. The main backbone is Wan2.2-TI2V-5B, fine-tuned for 5,000 steps (AdamW, lr 1e-5, batch 16); the model is also distilled into a four-step causal student with a KV cache for real-time inference.

**Limitation (≤3 sentences):** The authors state the method assumes the static world translates approximately rigidly in the image plane (true for top-down/isometric cameras that follow the player), so it does not model zoom or strong parallax, and does not make moving objects follow world coordinates. Knownness is defined only from the first frame's footprint, so regions revealed later aren't marked "known" when the camera returns to them. No GPU hardware is specified in the fetched text.

## ReDT: Resolution-Decoupled Visual Geometry Transformer
- **arXiv:** 2610.25517 · https://arxiv.org/abs/2610.25517
- **Submitted:** 2026-10-18
- **Authors:** Abteen Arab, Guile Wu, Dongfeng Bai
- **Qualifying affiliation(s):** Huawei Noah's Ark Lab — Abteen Arab (also University of British Columbia; footnote says work done during an internship at Huawei Canada), Guile Wu, Dongfeng Bai; FLAG: borderline
- **Categories:** cs.CV
- **Open release:** none found
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** ReDT is a feed-forward transformer for multi-view 3D reconstruction built on the VGGT family (specifically VGGT-Ω), designed to handle high-definition inputs without the quality degradation and quadratic cost that standard-definition-trained models show at higher resolutions. It maps each view to a fixed-size set of "basis tokens," computes cross-view correspondences in that compact space via Discretization-Invariant Visual Attention (DIVA) blocks, and projects results back to full resolution for dense prediction.

**Purpose (≤3 sentences):** The authors aim to let a visual geometry transformer trained at lower resolution generalize to much higher resolutions (SD to 2K) without retraining, motivated by an empirical finding that intermediate per-view features keep a nearly constant effective rank as resolution and view count grow.

**Breakthrough (≤3 sentences):** On ETH3D at 2K, the authors report a 16× speedup (6.35s vs 102.70s), 34% peak-memory reduction (64.47GB vs 98.09GB), and 33% Chamfer-distance reduction (0.1140 vs 0.1702) versus VGGT-Ω. On ScanNet++ (2K), they report pose AUC@30 of 93.65 vs 79.22 for DepthAnything3, the strongest baseline on that dataset.

**Tools & method (≤3 sentences):** The encoder uses a quadtree to merge low-entropy patches into 2×2/4×4/8×8 regions, and DIVA blocks replace standard attention with learned softmax assignments mapping N tokens to K fixed basis tokens, using test-time training (TTT) for cross-view reasoning in the basis space. Models are fine-tuned from public checkpoints for 10 epochs (AdamW) on seven datasets (ASE, ParallelDomain4D, UnrealStereo4K, MPSD, BlendedMVS, DL3DV, MegaDepth), with no GPU model specified but 100 FHD frames reported to need 61GB peak memory and ~8.2s.

**Limitation (≤3 sentences):** The paper has no dedicated limitations section, but the appendix states overall complexity remains quadratic in token count because the DPT decoder head is left unchanged, and peak memory still grows with resolution. The ablations show a smaller encoder basis count (256 vs 512) substantially hurts accuracy (Chamfer distance 0.3737 vs 0.1137), and on some sub-HD benchmarks the baseline FlashVGGT is faster.

## Map2Vid: Embodied Navigation Video Generation with Human-Friendly Motion Control
- **arXiv:** 2610.25223 · https://arxiv.org/abs/2610.25223
- **Submitted:** 2026-10-18
- **Authors:** Yulin Dai, Yuqian Fu, Tianwen Qian, Zhen Xing, Bojia Zi, Xiaoling Wang
- **Qualifying affiliation(s):** Alibaba Group — Zhen Xing (Qwen Team, Alibaba Group, Hangzhou)
- **Categories:** cs.CV
- **Open release:** none (paper mentions only an examples directory in supplementary material; no stated code/weights release)
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** Map2Vid frames embodied-navigation video generation as turning a bird's-eye-view (BEV) map of a scene and intended route into an egocentric video, as an alternative to vague text prompts or low-level camera-trajectory controls. The authors built Map2Vid-100K, a dataset of about 117.8K navigation sequences (94.2K train / 23.6K eval, ~211.6 hours of video) across 61 indoor scenes, pairing egocentric video with BEV maps, camera trajectories, and language instructions. Their framework fuses multiple control signals with curriculum training that gradually reduces reliance on non-map inputs, so it works with full conditioning or the map alone.

**Purpose (≤3 sentences):** The authors argue existing navigation-video controls are poorly suited to embodied navigation: text prompts are spatially vague, and camera-trajectory control relies on low-level motion parameters that are not human-friendly.

**Breakthrough (≤3 sentences):** The authors report that BEV-map control is a viable direction for navigation video generation across several tested foundation generation models, with curriculum training letting the model run on map-only input at inference. In zero-shot cross-scene and Sim2Real settings, geometric/trajectory control held up better than visual quality, which degraded sharply.

**Tools & method (≤3 sentences):** Benchmark built by replaying R2R trajectories in the Habitat simulator over Matterport3D scenes; evaluated with large DiT-based video generation backbones. The dataset (Map2Vid-100K) pairs BEV maps, camera trajectories, and language instructions with egocentric video.

**Limitation (≤3 sentences):** The authors state their conclusions are "limited to a simulation-based benchmark rather than real-world deployment," and that the dataset covers only static indoor layouts without dynamic obstacles or human-agent interaction. They also note precise orientation at sharp turns and translational stability remain challenging, with observed under/over-rotation and translation drift, plus substantial compute overhead from the large DiT backbones.

## MCSplat: Multi-View Photometric and Geometric Consistent Feed-Forward Gaussian Splatting for Driving Scenes

## Latent World Models Should Plan with Distances Along the Latent Manifold
- **arXiv:** 2610.25013 · https://arxiv.org/abs/2610.25013
- **Submitted:** 2026-10-18
- **Authors:** Zunzhi You, Linwei Tao, Siyu Xu, Yunke Wang, Chang Xu
- **Qualifying affiliation(s):** Apple — Linwei Tao (Machine Learning Research, Apple, in addition to University of Sydney)
- **Categories:** cs.LG (cross-listed cs.RO)
- **Open release:** code · https://github.com/youzunzhi/ngc-latent-manifold
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** The paper studies latent world models (e.g., LeWM) that plan by picking action sequences whose predicted latent is closest to a goal latent under Euclidean (L2) distance. The authors find L2 cost only works well near the goal; farther away it creates misleading low-cost regions that trap planners even though the latents still encode the true physical state. They propose the Neighborhood Graph Cost (NGC), which measures shortest-path distance over a mutual nearest-neighbor graph built from training latents, used only as the terminal planning cost with no retraining required.

**Purpose (≤3 sentences):** The goal is to fix long-horizon planning failures in latent world models caused by treating the latent space as globally Euclidean when it instead sits on a curved, low-dimensional manifold.

**Breakthrough (≤3 sentences):** The authors report NGC improves LeWM's planning success on all four tested benchmarks and nearly solves TwoRoom and Reacher; at the farthest goal offsets tested it reaches 95% and 100% success versus 27% and 81% for the L2 baseline. NGC requires no retraining of the world model, only a different terminal cost at planning time.

**Tools & method (≤3 sentences):** Evaluated on four benchmarks: TwoRoom, Reacher, Cube, and PushT, built on the LeWM latent world model. NGC builds a mutual nearest-neighbor graph over training-set latents and computes shortest-path (graph) distance as the terminal cost.

**Limitation (≤3 sentences):** The authors state NGC still falls short on the contact-rich Cube and PushT tasks even with an oracle predictor, because nearby physical states (e.g., a gripper near contact) can respond very differently to the same action, and contact introduces asymmetric transitions an undirected graph cannot express. They also note generalization to goals or environments outside the graph's coverage "remains untested."

## DragonMoCap: Monocular Video-based Motion Capture for Diverse Dragon Topologies
- **arXiv:** 2610.25437 · https://arxiv.org/abs/2610.25437
- **Submitted:** 2026-10-18

- **Categories:** cs.CV
- **Open release:** none found
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** DragonMoCap is a monocular video motion-capture framework for dragon-type game/film characters, whose production rigs vary widely in joint count (20–60+) and naming, breaking fixed-template regressors. It treats the target skeleton as a dynamic input via "language-grounded joint query tokens" (CLIP-encoded bone names plus topological/kinematic descriptors), with a non-parametric query-token retrieval mechanism for zero-shot adaptation to unseen rigs.

**Purpose (≤3 sentences):** The authors target the lack of parametric models and high-quality data for non-human (dragon) character mocap, which currently forces manual keyframing in animation production, covering three common topologies: winged quadrupeds, wingless quadrupeds, and winged bipeds (wyverns).

**Breakthrough (≤3 sentences):** The authors report DragonMoCap beats HMR-style baselines SMPLest-X and OSX on seen rigs (MPJPE 9.46cm vs 10.57cm for SMPLest-X, ~10.5% lower) and generalizes to 77 held-out unseen rigs (MPJPE 12.11cm vs 14.62–15.32cm for ablated variants), with 78.3% top-1 / 94.6% top-5 retrieval accuracy for bone-role matching in a leave-one-rig-out test. A 40-participant user study on AI-generated clips found DragonMoCap preferred over baselines for anatomical plausibility (mean 4.5 vs 3.2, 83.6% win rate, p<0.001), and the authors state the system has been integrated into professional animation workflows as a real-time Unreal Engine add-on.

**Tools & method (≤3 sentences):** Training uses an internal dataset of UE5-rendered, professionally animated dragon clips (88 training rigs / 77 held-out rigs, ~1.2M frames total after SLERP augmentation), with a frozen DINOv2 ViT-L/14 image encoder and frozen CLIP text encoder feeding a transformer decoder that predicts root translation and per-joint 6D rotations. Training used 4× NVIDIA A100 GPUs (batch 512, 200 epochs, AdamW, lr 2e-4), with inference at ~30 FPS on a single NVIDIA L20 GPU; the model is ~420M parameters (115M trainable).

**Limitation (≤3 sentences):** The paper has no dedicated limitations section, but the conclusion calls the image encoder's appearance coverage "the main remaining bottleneck," mitigated by generative appearance augmentation to reduce overfitting to limited visual diversity in the internal dataset. The user study used AI-generated inputs with no ground truth, so it measures perceived quality rather than accuracy, and the framework is scoped to three dragon topologies only.

## SwitchSplat: Learning Discrete Object States from Casually Captured Scenes
- **arXiv:** 2610.24812 · https://arxiv.org/abs/2610.24812
- **Submitted:** 2026-10-17
- **Authors:** Yizheng Xie, Yalda Foroutan, George Shramko, Daniel Rebain, Shrisudhan Govindarajan, Andrea Tagliasacchi
- **Qualifying affiliation(s):** Wayve Labs (Vancouver) — Daniel Rebain, Shrisudhan Govindarajan, Andrea Tagliasacchi. FLAG: borderline — Wayve is a UK autonomous-driving software company (backed by $1B+ rounds from NVIDIA, Microsoft and SoftBank) not on the explicit qualifying list, though comparable in standing.
- **Categories:** cs.CV (cross-listed cs.GR)
- **Open release:** none found for code/dataset; project page at https://switchsplat.github.io
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** SwitchSplat extends 3D Gaussian Splatting to casually captured scenes containing discrete object-state interactions (e.g., opening a door, toggling a switch), which standard static 3DGS and time-conditioned 4DGS methods can't model without tying state to a specific recorded timestamp. It decomposes the scene into a shared static base plus per-object "slots," each modeling one interactable object's on/off states, with a differentiable Gaussian-to-slot assignment learned directly from video without manual annotation. At inference, users can recombine slot states and render from any viewpoint, including unseen state combinations.

**Purpose (≤3 sentences):** The goal is to let 3D Gaussian Splatting represent scenes with discrete interactable object states from ordinary casual video capture, rather than only replaying the exact recorded state sequence as 4DGS does.

**Breakthrough (≤3 sentences):** The authors report SwitchSplat outperforms static and dynamic (4DGS-style) baselines on a new casual-capture dataset and can render state combinations that were never observed together during capture. The method assumes binary object states and single-operator, one-free-hand capture.

**Tools & method (≤3 sentences):** Uses a VLM to seed the number of interactable slots and approximate interaction timing, with per-part geometry learned via a differentiable Gaussian-to-slot assignment. Evaluated on a new custom casual-capture dataset (indoor and outdoor scenes); outdoor evaluation excludes dynamic background regions (foliage, sky, street activity) from some metrics.

**Limitation (≤3 sentences):** The authors state the method assumes binary (not continuous or multi-valued) object states and single-operator capture, and that "fully unsupervised discovery of both the number and timing of interactions from raw video remains an open problem" since slot count/timing are VLM-seeded. The work is scoped to novel-view synthesis; combining it with physics or generative priors for scene editing/simulation is left to future work.
