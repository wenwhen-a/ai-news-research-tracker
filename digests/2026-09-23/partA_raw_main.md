## GameDirector: Decoupling Gameplay Logic from Rendering for Player-Configurable Game World Models
- **arXiv:** 2609.25652 · https://arxiv.org/abs/2609.25652
- **Submitted:** 2026-09-22
- **Authors:** Zijun Lin, Zhiyang Deng, Yuzhe Wu, Bihan Wen, Yeying Jin
- **Qualifying affiliation(s):** Tencent — Zijun Lin, Zhiyang Deng, Yuzhe Wu, Yeying Jin (all also list Singapore-based academic affiliations: NTU, NUS, A*STAR)
- **Categories:** cs.CV
- **Open release:** none stated (project page only: https://jimntu.github.io/gamedirector/, no code/weights commitment in the paper text)
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** GameDirector is presented as "the first agentic framework that decouples rule-based gameplay logic from visual rendering" in game world models. Given player configurations, it interprets observations, updates explicit game state, controls NPCs, and enforces rules, then translates decisions into text prompts for a video world model. The authors report it "improves boss action quality by more than 39.9% over various end-to-end game world model settings" across three games.
**Purpose (≤3 sentences):** The paper argues existing end-to-end game world models combine perception, memory, state transitions and rendering in one pixel-supervised model, which "still falls short of delivering a complete gameplay experience" because games need explicit mechanics like health deduction and combat rules that generative models cannot reliably enforce. GameDirector aims to separate deterministic gameplay logic from generative visual rendering so mechanics stay rule-accurate while visuals remain generative.
**Breakthrough (≤3 sentences):** The authors report the framework achieves accurate state tracking and improved boss action quality (>39.9%) versus end-to-end baselines across three games: "No Rest for the Wicked," an anonymized vampire-themed game, and "Hollow Knight." Deployment is reported at roughly 17 FPS on one-, two-, and four-GPU configurations (attributed to the authors; no third-party benchmark cited).
**Tools & method (≤3 sentences):** Two ResNet-18 models (SituationNet for character distance/angle, AttackNet for hit detection) process frames at different sampling frequencies; an explicit state tracker deterministically updates health points and boss skill meters from detected hit signals. A 2B-parameter language model (Gemma-4-E2B-it) selects boss skills from spatial context without task-specific fine-tuning, and a rule-enforcement layer validates actions before passing them to Wan2.2-TI2V-5B, the video world model, fine-tuned on a 51,786-clip (71.93-hour) dataset covering 13 characters across the three games; training used four GPUs.
**Limitation (≤3 sentences):** The authors note the framework's accuracy depends on its learned perception modules, stating "errors in the underlying hit detection are separately characterized by AttackNet accuracy." They also flag concurrent work using game engines or coding agents for structured intermediate representations as a related direction, implying their current perception-based state tracking is one of several possible approaches, and describe extending toward more "structured and controllable settings" as future work.

## Code Plans, Diffusion Renders: Open-Ended Generative World Modeling
- **arXiv:** 2609.26458 · https://arxiv.org/abs/2609.26458
- **Submitted:** 2026-09-22
- **Authors:** Zixun Fang, Yawen Shao, Kai Zhu, Jie Xiao, Shihan Chen, Yu Liu, Xueyang Fu, Yang Cao, Wei Zhai, Zheng-Jun Zha
- **Qualifying affiliation(s):** Alibaba — TongYi Lab co-authors (alongside USTC academic co-authors)
- **Categories:** cs.CV
- **Open release:** planned — "Code and model weights will be made publicly available" (project page: becauseimbatman0.github.io/CoDeR); no functioning release link confirmed at time of check
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** CoDeR is a world-modeling system that explicitly constructs an executable world using code, then uses a video generation model for visual realization, rather than implicitly encoding dynamics purely in a video model's weights. Five coordinated roles ("God of Concepts," "Creator," "Executors," "Artists," "Travelers") translate high-level concepts into world rules, executable dynamics, and rendered observations. The authors report state-of-the-art results on WorldScore and VBench benchmarks (attributed; no third-party verification found).
**Purpose (≤3 sentences):** The paper targets limitations of existing video world models, which represent dynamics only implicitly through visual observations, limiting long-term memory, open-ended interaction, autonomous evolution, and multi-agent persistence. CoDeR aims to give a world model explicit, code-level structure so entities can "act, interact, and evolve persistently beyond the current observation."
**Breakthrough (≤3 sentences):** The authors report their framework "substantially extends the capabilities of existing world models" on long-term memory, open-ended interaction, autonomous evolution and persistent multi-agent dynamics, with state-of-the-art performance across multiple evaluation settings (WorldScore, VBench) as they state it. A distinguishing technical claim is "Observation as World Registration," where generated video frames are registered back into the explicit world model via depth maps so prior rendered appearance informs later generation.
**Tools & method (≤3 sentences):** The Creator/Executor roles run on "GPT-6 Astra," described as an advanced multimodal LLM-based coding agent, generating executable code for a whitebox 3D world built in Three.js; human/hand-object motion is represented with SMPL-H. The Artist role uses "MiniMax H3," described as a state-of-the-art open-source video generation model, trained on 32 NVIDIA A800 GPUs at global batch size 16 for 200 steps, generating 1280×704 video at 124 frames per clip.
**Limitation (≤3 sentences):** The authors state that at roughly 5,000 frames, "noticeable degradation appears" due to accumulated errors from chunk-based generation. They also acknowledge the whitebox model struggles to accurately represent complex hand-object interactions (citing observed geometric distortion and object interpenetration), and that the current Artist model generates RGB observations where geometry, material, illumination and appearance remain "implicitly entangled" rather than separately controllable.

## SAM-V: Geometry-Aware Segment Anything for Multi-View Instance Segmentation
- **arXiv:** 2609.25490 · https://arxiv.org/abs/2609.25490
- **Submitted:** 2026-09-21
- **Authors:** Jiangshan Gong, Yuqun Wu, Qiqian Fu, Yao Xiao, Chuhang Zou, Shenlong Wang, Derek Hoiem
- **Qualifying affiliation(s):** Meta — affiliation listed on the paper (specific author not distinguished in the visible author block; primary team is University of Illinois Urbana-Champaign); FLAG: borderline — Meta co-authorship confirmed on the page but not cleanly attributed to a specific named author in the fetched content
- **Categories:** cs.CV, cs.LG
- **Open release:** code + weights — "Our code and pretrained models are available" at https://github.com/gong208/SAM-V.git
- **Shipped counterpart:** none found

**Summary (≤3 sentences):** SAM-V integrates a feed-forward geometry model (VGGT) into the Segment Anything (SAM) foundation model, training the combination end-to-end for consistent object segmentation across multiple camera views in a single forward pass. A prompt-fusion mechanism combines view-specific camera tokens with spatial features so a single prompt in one view yields consistent masks across other views. The authors report a 5-point overall IoU and 12-point frame-level recall improvement over existing baselines on the IGGT 3D tracking benchmark (ScanNet++), as they state it.
**Purpose (≤3 sentences):** The paper targets consistent multi-view object segmentation for 3D perception and robotics applications, where evaluating views independently cannot guarantee they describe the same object instance across viewpoints. It aims to avoid offline processing or explicit 3D reconstruction by producing consistent multi-view segmentation directly.
**Breakthrough (≤3 sentences):** The authors report SAM-V achieves "5 points [improvement in] overall IoU and 12 points on frame-level recall" over baselines on ScanNet++ (IGGT benchmark), plus leading performance in zero-shot evaluation on ScanNet, as they state it. The method reportedly requires no offline processing, producing multi-view-consistent segmentation "in a single forward pass."
**Tools & method (≤3 sentences):** SAM-V fuses frozen SAM (ViT-H) and VGGT encoders via a trainable MLP feature-fusion module and a cross-attention prompt-fusion module that combines camera tokens with local VGGT features; only the fusion modules and SAM's mask decoder are trained, with a combined focal, Dice, and IoU-prediction loss. Training is two-stage: pretraining on synthetic Hypersim (612 scenes, 212 epochs) then finetuning on ScanNet++ (856 scenes, 20 epochs), using 8–14 NVIDIA L40S GPUs, with single-L40S inference.
**Limitation (≤3 sentences):** The authors state SAM-V is "trained only on indoor datasets (Hypersim and ScanNet++), and generalization to outdoor or object-centric domains remains untested." They also state the method assumes rigid objects in static environments, noting "handling deformable entities or dynamic scenes will require spatial-temporal modeling," and that it focuses on prompt-conditioned rather than open-vocabulary/language-guided segmentation.
